# Once-per-boundary-plan certificate for mid-step velocity halos

Run `python3 -B mpi/haloepochs/corner.py --source PARENT/source --out NEW_DIR`. Overlay **all four** emitted files (`mpideck`, `mpi_boundary.f`, `extrnl.f`, `secom_mpi.f90`) and rebuild all objects that include the deck. Do not change the established MPI DOMAIN log format. The rank-zero stdout line `MPI CORNER PLAN LOCALBC=T KEEP_UA=F KEEP_VA=F`, together with the separate `OWNED_OUTER T` report, shows both skips are eligible on this rotating private kernel. The constructor defaults and INIT/FINALIZE reset both keep flags to true. Standalone/nonrotating, uncertified and non-outer paths remain unchanged. A model that mutates geometry after startup must re-plan before relying on this or on the original boundary certificate.

The EXTRNL entry already publishes or reuses south UA and north VA. Until post-corner momentum, the admitted branch's only writers of either field are the ordered corner assignments. BCOND12 writes ELF, ADVAVE computes scratch/accelerations, and loop 310 writes curvature/shear. Momentum 425 needs north VA; 435 needs south UA. A target UA row `j` needs re-publication iff `j < JM && owner(j) != owner(j+1)`. A VA target row `jv` needs it iff `jv > 1 && owner(jv) != owner(jv-1)`. Bottom types 1/2 write `(UA:j, VA:j+1)`, top 3/4 write both at `j`. Two separate integer MAX collectives at startup admit any rank's veto; they cost nothing per substep. Never collapse independent Boolean flags using an integer MAX of a combined bitmask. All ranks take the same branch and keep both existing synchronization points on CURV42D and ELF.

An eligible bottom corner has `j,j+1,j+2` on one owner; its VA target cannot be that owner's first row. An eligible top corner has `j,j-1` on one owner and likewise cannot write that owner's first VA row. Thus an interior VA-at-first counterexample necessarily fails the stronger existing LOCALBC gate first. The explicit VA check is retained conservatively. By contrast, a top corner may validly update UA on the last row of its owner; this is the critical positive veto.

Native `p3-corner-r014a.json` / `.log` include 3×1 and 2×2 real eight-step EXTRNL/WAD/CHECK captures (24 owned planes and selected extrema), compared against the corresponding slices of a separate single-rank run. They cover allowed skips, UA-only veto, stronger LOCALBC rejection, OUTER rejection and no-corner geometry. Deliberately dropping a vetoed UA publication changes a neighbor's first-step VA and fails the comparison. A separate real geometry/consensus test runs six cases in 1-, 2-, and 3-rank layouts, including a single reporting rank's veto. Reproduce by staging `old`, `cert`, `bad-skip-ua` using `test_corner.py stage DIR/ROLE --source PARENT/source --role ROLE`; run `native_entry.py DIR --corner --cpus <reserved cores>` only when the physical CPUs have been allocated for the unit. No solver timing is claimed by this test.
